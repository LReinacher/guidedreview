# Keyboard shortcuts

Move through a guided review without leaving the keyboard. Focus must not be in an editable field for most of these — when the comment composer is open, typing goes to the text field and only Esc / ⌘/Ctrl+Enter are intercepted.

The Guided Review sidebar always lists the same shortcuts as this page. Most chords work in both the [Chrome extension](/docs/first-review) and the [CLI](/docs/cli); [Local review](#local-review) adds CLI-only keys. Submit chords apply to the extension only.

## Review navigation

| Shortcut           | Action                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------- |
| `→`                | Next Unit                                                                                       |
| `←`                | Previous Unit                                                                                   |
| `↑` / `↓`          | Scroll the Code Pane                                                                            |
| `Esc`              | Exit Guided Review (when not in comment mode or a modal)                                        |
| `c`                | Enter [Comment Mode](/docs/leave-comments) (if the unit has selectable lines)                   |
| `⌘/Ctrl` + `F`     | Open [Diff Search](#diff-search)                                                                |
| `⌘/Ctrl` + Click   | Preview Where a Symbol Is Declared ([Go to definition](#go-to-definition))                      |
| `⌘/Ctrl` + `Enter` | Open [Submit Review](/docs/submit-review) (or [Connect GitHub](/docs/connect-github) if needed) |

On a GitHub PR, while Guided Review is open, keys are not passed through to GitHub’s page shortcuts. What a “unit” is: [How a review plan works](/docs/how-it-works#review-units).

## Diff view

| Shortcut     | Action       |
| ------------ | ------------ |
| `v` then `u` | Unified View |
| `v` then `s` | Split View   |

Type `v`, then `u` or `s` within about a second. You can also toggle unified / split from the toolbar while [following the walkthrough](/docs/first-review#walk-the-plan).

**Default is split.** In the extension, your choice is remembered in `chrome.storage.local` for the next review on this browser.

## Diff search

Search **every** file path and line in the parsed diff — not only the active unit.

1. Press `⌘/Ctrl` + `F` while the overlay is open.
2. Type a path fragment or code snippet. Results are fuzzy-ranked (paths rank above line hits).
3. Move with `↑` / `↓`, open a hit with `Enter`, or close with `Esc`.
4. Selecting a result jumps to the unit that owns that file (or hunk) and scrolls the match into view.

Press `⌘/Ctrl` + `F` again while the palette is open to re-focus and select the query. Renames match on the old or new path. Binary / elided files contribute path hits only.

This is Guided Review’s own search palette. On a PR page, GitHub’s find does not run while the overlay owns the keyboard.

## Go to definition

Hold `⌘/Ctrl` and click a function, class, or type in the diff. Identifiers underline while the key is down, and a click opens a card with the declaration — path, line, and the source itself — before you go anywhere.

The card holds the declaration plus the lines around it — scroll inside it to read the rest of the body without leaving the review.

Lookup follows the order a reader expects:

1. **What the name is bound to in the file you clicked in** — a parameter, a local, a `const` in an enclosing block. Clicking an argument resolves to the parameter it arrived on, not to a same-named local somewhere else in the repo.
2. **The module it was imported from**, when the import is relative and the file is in the repo. Package imports and path aliases are not resolved to a file, but the module name still ranks the candidates.
3. **The rest of the repository**, with test files last unless you clicked in one.

From the card:

- **Open in New Tab** — the file at that line. The CLI opens its own source viewer; on a PR page it opens the file on GitHub.
- **Jump to It** — only when the declaration is part of the diff you are reviewing. Moves the walkthrough to the unit that owns it and scrolls the line into view.
- `‹` / `›` when several files declare the same name. Declarations in the file you clicked from, then its directory, rank first.
- `Esc` closes the card and leaves the review exactly where it was.

What can be found depends on where the review runs:

| Host                                           | Searches                                                                               |
| ---------------------------------------------- | -------------------------------------------------------------------------------------- |
| **[CLI](/docs/cli)**                           | The whole repository, including files the branch never touched and new untracked files |
| **[Chrome extension](/docs/chrome-extension)** | The diff itself — declarations the PR adds or keeps                                    |

This is pattern matching, not a language server: it reads declaration shapes for the file's language out of candidate lines, and scope from indentation. It finds ordinary functions, classes, types, methods, constants, parameters and imports; it will not resolve a symbol that is built at runtime, generated, or defined in a dependency, and on a name that several modules declare it can still offer the wrong one. That is why the card previews first and moves second.

## Comment mode

| Shortcut           | Action                                             |
| ------------------ | -------------------------------------------------- |
| `↑` / `↓`          | Move the Line Cursor                               |
| `⇧` + `↑` / `↓`    | Extend Multi-Line Selection                        |
| `Enter`            | Open the Comment Composer on the Selection         |
| `⌘/Ctrl` + `Enter` | Save Draft (composer open)                         |
| `Esc`              | Close Composer, or Exit Comment Mode               |
| `←` / `→`          | Previous / Next Unit (still works in comment mode) |

Details and draft editing: [Leave line comments](/docs/leave-comments). Drafts stay local until submit: [Privacy & data](/docs/privacy-and-data#what-stays-local).

## Submit and modals

| Shortcut            | Action                                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `Esc`               | Close the Topmost Modal (submit, connect GitHub, confirmation) without exiting the whole review when a modal owns focus |
| `↑` / `↓` / `Enter` | Choose Review Type on the Submit Dialog                                                                                 |
| `⌘/Ctrl` + `Enter`  | Submit from the Compose Step                                                                                            |
| `Enter` / `Esc`     | Dismiss the Post-Submit Success Dialog and Exit                                                                         |

Full submit flow: [Submit a review](/docs/submit-review). Auth gate: [Connect GitHub](/docs/connect-github). If submit fails: [Troubleshooting](/docs/troubleshooting#github-connect-and-submit).

## Local review

The [CLI](/docs/cli) uses the same navigation, diff view, search, and comment-mode keys as the extension. Submit (`⌘/Ctrl` + `Enter` for a GitHub review) does not apply — use [Generate Prompt](/docs/generate-prompt) from the UI instead (needs at least one note). Extra in the local UI:

| Shortcut       | Action                       |
| -------------- | ---------------------------- |
| `d`            | Open the Diff-Scope Dropdown |
| `⌘/Ctrl` + `I` | Structure With AI            |
| `⌘/Ctrl` + `,` | Settings                     |

## Marketing site

On [guidedreview.dev](https://guidedreview.dev):

| Shortcut       | Action                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------- |
| `⌘/Ctrl` + `I` | Jump to the Install Section on the Homepage                                                     |
| `⌘/Ctrl` + `E` | Open the Chrome Web Store Listing — also [Chrome Extension](/docs/chrome-extension)             |
| `⌘/Ctrl` + `C` | Copy the CLI Install Command (`npx @guided-review/cli`) when the Install section is on the page |
| `⌘/Ctrl` + `G` | Open the GitHub Repository                                                                      |

> **Tip.** Prefer keyboard navigation on large plans — it keeps attention on the unit narrative instead of hunting scroll position on the PR page.
