# CLI

The [Chrome extension](/docs/chrome-extension) reviews GitHub pull requests. The **CLI** reviews a local branch, a commit, or your working tree with the same engine and walkthrough — before you open a PR, or when there isn’t one. It does not structure the walkthrough with AI until you ask. Choosing between hosts: [Install](/docs/install).

## Run it

Node.js 22 or newer:

```bash
npx @guided-review/cli
```

Pass flags after the command:

```bash
npx @guided-review/cli --base main --no-open
```

The published package is `@guided-review/cli`. The binary is `guidedreview`. `npx guided-review` (unscoped, hyphen) is a different package. From this repo: `pnpm build:cli` then `pnpm review` (flags after `--`).

The CLI binds `127.0.0.1:7182` (ASCII G+R), keeps a short terminal banner (URL, diff, last pull), and opens the UI unless you pass `--no-open`. Only real events (structure, scope change, errors) go to the log below. Override with `--port`. `--port 0` picks any free port. Ctrl+C stops the server.

## What it compares

The header shows the current branch and the base branch. A dropdown picks the diff:

- **Branch vs base** — committed work on this branch since it diverged from the base (`git diff <merge-base> HEAD`)
- **Uncommitted** — staged and unstaged work versus `HEAD` (untracked files included unless you passed `--no-untracked`)
- **Unstaged** — worktree versus the index only
- **A specific commit** — that commit’s patch

Default selected scope: the first non-empty of branch, uncommitted, unstaged, then the newest commit. `--staged` starts on index-only uncommitted work.

Base resolution, in order: `--base` → `origin/HEAD` → `main` → `master`.

If every scope is empty: `Nothing to review against <base>.` and exit 0. Not a git repo: an error that says what failed.

## Follow the Walkthrough

The walkthrough starts **one unit per file**. **Structure With AI** on the Change summary card is the opt-in LLM call — same pipeline as the extension ([How a review plan works](/docs/how-it-works)). It groups files and adds context; it does not review for you.

Press `d` to open the scope dropdown, `⌘/Ctrl` + `I` to structure, or `⌘/Ctrl` + `,` for Settings — same keys as [Keyboard shortcuts → Local review](/docs/keyboard-shortcuts#local-review). Navigation, diff search, and comment mode share the extension shortcuts where they apply.

Comments are kept as you write them and survive restarting the CLI. When the branch has an open pull request you can [submit them as a review](#posting-to-github); otherwise they feed [Generate Prompt](#notes).

## API keys

Same providers as the extension: Anthropic, OpenAI, Grok. Full setup (including borrowing a coding-agent subscription): [Configure AI provider → CLI](/docs/configure-provider#cli).

Resolution, in order:

1. `--provider` / `--model` / `--agent` and env (`ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `XAI_API_KEY` or `GROK_API_KEY`)
2. A key already saved in `~/.config/guided-review/config.json`
3. A coding agent already on this machine (Claude Code, Codex, or Grok)

If more than one agent is usable, the CLI asks which to use each run (Enter keeps the last choice). The chosen agent is shown in the browser UI, and nothing it holds is copied into Guided Review config.

Claude Code is used by running it: the CLI spawns `claude -p` and Claude Code authenticates with your existing login, so a Claude subscription works (it needs `claude` on your `PATH`). Codex and Grok instead lend a stored token to a direct provider API call, which is unofficial and can break — see [Configure AI provider → CLI](/docs/configure-provider#cli).

No key still walks one unit per file. **Structure With AI** asks for a key.

The local UI has **Settings** (header, `⌘/Ctrl` + `,`, or **Connect AI Provider** when no key is set). Paste an API key, or turn on **Use My Subscription** to use Claude Code / Codex / Grok on this machine. A saved API key always wins. Save writes the [config file](#config-file) below. Flags and env still win for that run.

## Collapsed lines

Where a patch skips lines between two hunks, the diff shows a bar with the number of hidden lines. Click `↓` or `↑` to reveal 20 more from either end, or **Expand N Hidden Lines** when the rest fits in one step. The CLI reads them from the file on disk, so this only works for text files still present in the reviewed scope.

## Config file

Saved prefs live at `~/.config/guided-review/config.json`, or:

- `$XDG_CONFIG_HOME/guided-review/config.json` when `XDG_CONFIG_HOME` is set
- `$GUIDED_REVIEW_CONFIG_DIR/config.json` when that env var is set (wins over XDG / home)

Example shape (all fields optional — only what you saved appears):

```json
{
  "provider": "anthropic",
  "model": "claude-opus-4-8",
  "apiKey": "sk-ant-…",
  "codingAgent": "claude-code"
}
```

| Field         | Meaning                                                               |
| ------------- | --------------------------------------------------------------------- |
| `provider`    | `anthropic` \| `openai` \| `grok`                                     |
| `model`       | Provider model id (any id your account can call)                      |
| `apiKey`      | Console API key for that provider                                     |
| `codingAgent` | `claude-code` \| `codex` \| `grok` when using **Use My Subscription** |

Prefer editing through **Settings** in the UI. If you hand-edit the file, restart the CLI (or re-open Settings and save) so the running server picks up the change. Flags and env still override the file for that run. Clearing a key: remove `apiKey` from the file, or clear it in Settings — [Privacy & data → Clear data](/docs/privacy-and-data#clear-data-and-disconnect).

## Notes

A review is saved as you go, under `.git/guided-review/sessions` in the repo you are reviewing. Close the tab or lose the process and the next run resumes the same review — the structure it built, where you were, and every comment you had written, posted or not. Saved reviews are keyed by base, branch, and scope, and never leave the clone.

**Generate Prompt** builds a coding-agent prompt from your notes and copies it — Guided Review does not send it anywhere. Full walkthrough: [Generate Prompt](/docs/generate-prompt).

### Posting to GitHub

When the branch has an open pull request and this machine has GitHub credentials, **Submit Review** posts a real pull request review: your inline comments, a summary, and Comment / Approve / Request changes — the same flow as [the extension](/docs/submit-review). Generate Prompt stays available beside it.

Credentials come from `gh auth token`, or from `GH_TOKEN` / `GITHUB_TOKEN`. There is nothing extra to log into and Guided Review stores no token of its own.

Every comment picks a destination as you write it:

- **GitHub** — posted as an inline comment when you submit the review
- **Local** — stays on this machine, and only feeds Generate Prompt

GitHub anchors review comments to the pull request head. Reviewing uncommitted work, a single commit, or a branch you have not pushed can therefore land comments on the wrong lines, so the submit dialog says so before you post. Pass `--no-github` to turn submission off entirely.

## Flags

```
guidedreview [dir] --base main --port 8787 --no-open --staged --no-untracked --agent claude-code
```

| Flag              | What                                    |
| ----------------- | --------------------------------------- |
| `--base <ref>`    | Base branch                             |
| `--port <n>`      | Listen port (default `7182`)            |
| `--no-open`       | Print the URL without opening a browser |
| `--staged`        | Start on staged changes                 |
| `--no-untracked`  | Skip untracked files                    |
| `--no-github`     | Never offer to post to the branch's PR  |
| `--provider <id>` | `anthropic` \| `openai` \| `grok`       |
| `--model <id>`    | Provider model id                       |
| `--agent <id>`    | `claude-code` \| `codex` \| `grok`      |

Problems starting the server or structuring a plan: [Troubleshooting → CLI](/docs/troubleshooting#cli).
